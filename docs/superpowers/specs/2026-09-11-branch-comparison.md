## 本机启动位置

相对于主仓库 `C:/Users/nashorya/my-AI-Vtuber`：

- 旧版：`artifacts/branch-comparison/builds/legacy/AIVTuber.exe`
- 新版：`artifacts/branch-comparison/builds/invited/AIVTuber.exe`

两版一次只启动一个，避免同时占用麦克风、内录、ASR 和弹幕端口。各自的 `config.json` 是当前运行目录配置的副本；各自的 `memory.db` 是同一原数据库的独立快照。后续修改不会写回原运行目录。配置和数据库均未加入 Git。

旧版保留其原有关键词门控：PK 模式需命中配置中的唤醒词，随后默认保持 45 秒。当前配置的角色提示词称“大肥鱼”，唤醒词则是“小鲸鱼、小金鱼”；原样旧版不会把这些自动视为同一个名字。若只想对比由提示词决定是否发言，可在旧版配置界面切到普通模式，并在测试记录中注明这一配置变化。

新版让模型根据角色名、别名、双方近期对话判断邀请；“她昨天说……”默认旁听，直接提问、单独叫名及承接追问才回应。对话记录与是否回答分开，静默、模型出错或停止时都保留已识别文字。

新版在最后一条识别文本后合并 350 ms，连续新文本最多延长到首条后的 1000 ms。该上限仅指空闲时的合并等待，不包含 VAD 分段、ASR、模型、TTS 和上一轮播放耗时。开始生成后普通新话进入下一轮；截停按钮或独立的“等等、先别回答、先别说了、停止回答、停止说话”会取消。

模型输出使用 `respond` 布尔值与 `speech` 正文两个 JSON 字段。只有验证通过的公开正文能进 TTS。PASS 大小写及两种括号形式均作静默兼容，格式错误直接丢弃并显示错误。

## 验证与实聊边界

- 旧版 Core：419 项通过；Release publish 成功。
- 新版 Core：542 项通过；App.Tests：1 项通过；Release publish 成功。
- 新增覆盖：单句自动触发、持续输入最大等待、捕获顺序、合成期间新输入不作废回答、停止/关闭、双方上下文在静默及无提交情况下仍可用、JSON/旧式 PASS 不进入 TTS，以及请求完成后立即接下一轮。
- 未启动真实直播或进行麦克风/远端模型/TTS 实聊。模型“接话分寸”须以实聊检验，单元测试不能证明其语义判断质量。
- 沿用了现有 API、模型和本地 ASR 配置，没有验证服务可用性。当前 LLM 模型配置含 `expires-on-0910`；若出现模型不存在/过期错误，需要在界面选择账号仍可用的模型。
- 两版都沿用播放时暂停内录的防自听机制，因此无法保证捕获 AI 播放期间对方主播的每一句话。未识别到的音频不会出现在模型上下文里。

## 建议按同一段对话试听

1. 双方先聊火锅偏好，AI 不插话。
2. 说“她上次说那个挺搞笑”，继续和对方聊，AI 保持旁听。
3. 问“大肥鱼，你觉得刚才哪种好？”：回答应引用刚才双方观点，不重新询问话题。
4. 接着问“为什么？”：无需重复名字即可追问。
5. 转向对方主播问“那你呢？”：AI 回到旁听。
6. 她生成时说“嗯嗯”：已有回答应完成；说“先别回答”：应停止。
